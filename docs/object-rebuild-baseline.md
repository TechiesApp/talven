# Correctness-gated native rebuild comparison

Status: implemented offline measurement runner for [private object reuse](object-reuse.md), with [one retained local run](object-rebuild-evidence.md). These are trusted local build measurements, not model trials, production latency guarantees or watcher readiness evidence.

~~~sh
python3 scripts/measure-unit-rebuilds.py --out build/unit-rebuilds \
  --repetitions 3 --warmups 1 --timeout 60 --stable-toolchain \
  --environment-note 'Describe CPU, host load and trusted stable toolchain'
~~~

The output directory must be new. The runner requires a trusted GCC/Clang-compatible C11 driver, a POSIX host and the object API's explicit stable-toolchain assumption. It never invokes a model/provider. `--expect-arch` checks the actual host; running on a Mac does not establish a new language target profile. CI retains a one-repetition correctness run for each declared Linux architecture/Python job; shared-runner timings are evidence, not general guarantees.

Reuse the four [persistent-check edit workloads](incremental-checking-baseline.md): 32/128-helper chains, a 128-helper scalar-store chain, and borrowing. Each has initial, shifted-comment, changed-body, changed-global-contract, invalid and repaired revisions. Chains and borrowing use independent C drivers checking three full i32 inputs; borrowing additionally verifies owners, stores and preservation of an added field. The workload factory retains exact source and oracle bytes for every revision.

Compare two end-to-end in-process build boundaries. `full` freshly analyzes and emits ordinary whole-program C, then performs one compile/link command. `units` freshly analyzes/preprocesses, probes the driver, verifies/copies retained objects, compiles misses and links a candidate. Both use the same effective inherited environment and strict C11/O2/warnings/no-LTO settings. Unit initial timings include session construction; each repetition starts a new session, then follows the same edit sequence. Alternate full/units ordering by repetition. Neither timing includes frontend process startup, independent verification, archive copying or final session cleanup; replacement cleanup performed inside the build is included. Warmup repetitions are retained but excluded from summaries. This is not a like-for-like single C-command comparison: the prototype's actual fresh preparation/probe costs are included.

Before timing, independently analyze each revision and compile/run its ordinary-C oracle. After each successful timed build, retain executable identity and require current program exit zero/empty output. Whole builds must emit the exact accepted C. Unit receipts must describe current source/compiler/configuration and partition every current unit into compiled/reused lists. Link an independent driver against the **actual candidate objects**, excluding only the generated C entry wrapper, and execute its full-value/owner checks. Confirm object and executable bytes match the receipt. Expected invalid revisions must return the current full diagnostic; failure is a measured rejection, not successful native acceptance. Repair checks occur within the same session.

The runner saves every sample before attempting it and saves its duration before verification. Unexpected tool, native, identity or correctness failure leaves `complete: false`, `passed: false`, `summary: null`, partial samples and archived command outputs. A summary requires all measured workload/revision/mode groups to contain the requested number of verified nonnegative integer durations. A test deliberately supplies wrong actual objects with forged source metadata: the independently linked native driver rejects them, preventing summary publication.

Receipts retain source/compiler/language identities, selected driver/Python executable hashes, driver version/target, flags, hardware/OS, wall-clock range, monotonic clock details, repetition/order, GC configuration, timeout, effective-environment hash, exact input archive hashes, source/oracle hashes, work receipts and native verification commands/output. Environment values are not dumped; named fixed child overrides are recorded. Raw artifacts can contain host paths and trusted compiler output and are local evidence. The initial Python hash-seed setting is recorded; changing its environment variable within the runner does not retroactively change the running interpreter's seed.

Source archives include all compiler modules, runner dependencies, workload factory, experiment package entry point and top-level examples so the retained workload generator can be replayed. Recheck input and selected executable identities before marking completion. These hashes are unauthenticated byte identities, not a complete reproducible or trusted toolchain archive. Compilers may produce differing binaries and OS caches remain warm/uncontrolled. Resource limits belong to the underlying build API; verification commands use the existing measurement recorder and timeout.

Unmeasured: memory, cold OS caches, production frontend/backend choice, native Rust reuse, watcher cancellation, save-to-diagnostic/readiness, running-process replacement, state preservation, agent token/dollar cost and broader workloads. Report each edit/condition independently; do not infer a consistent speedup from object reuse alone.

[Proposal 0026](proposals/0026-local-function-contracts.md) adds explicit [local function contracts](local-function-contracts.md) for hosted units and native watch mode. It retains current full checks, global record layouts and default profiles while allowing unrelated declarations and parameter names to stop invalidating callers. Both native measurement runners accept `--local-contracts`; performance conclusions require retained comparative evidence.

[Three same-checkout paired comparisons](local-contracts-evidence.md) retain actual native acceptance and reduced parameter-rename invalidation, with mixed cold/other edit costs. Existing defaults remain unchanged.
