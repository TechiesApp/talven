# Native watcher edit measurement

Status: implemented offline measurement of the default full-build watcher and the [opt-in private native object watcher](native-watch.md), under [Proposal 0025](proposals/0025-native-object-watch.md). The first [local observations](native-watch-evidence.md) show mixed edit costs and higher native cold/global costs. Running the measurement establishes only its recorded host, source, toolchain, polling and correctness evidence. It does not establish a general speedup, application readiness or hot reload.

~~~sh
python3 scripts/measure-native-watch.py --out build/native-watch-baseline \
  --repetitions 3 --warmups 1 --timeout 60 --stable-toolchain \
  --environment-note 'Describe the host, competing work and cache conditions'
~~~

Use a new output path. The explicit stable-toolchain acknowledgement applies to the native object mode and its inherited trusted toolchain assumptions. This experiment requires the same hosted POSIX/GCC-or-Clang C11 interface as the watcher. The declared architecture is checked if `--expect-arch` is supplied. There are no model/provider calls.

## Inputs and correctness

Use the existing chain-32, chain-128, stores-128 and borrowing workload families, with initial, trivia, body, contract/schema, invalid and repair revisions. Each watched main contains independently specified checks over three full integer inputs, not only a greeting or the compiler's successful return code. Borrowing main also checks owner updates and preservation of the added boolean field. Successful main prints exactly `accepted` followed by a newline and exits zero; an incorrect value returns one before printing. Trivia changes preserve all emitted units; body edits change helper behavior and corresponding independently specified main expectations; contract/schema changes conservatively affect global contracts. Invalid edits must produce the exact current full frontend diagnostic.

Before timing, archive every source and analyze it independently. For valid revisions emit ordinary console C, compile it without LTO and link a separate C oracle checking helper values and owners; execute that oracle and main. This independently verifies the specified workload rather than interpreting a reuse receipt as task correctness.

Start a new real CLI watcher session per workload/mode/repetition and follow the entire edit sequence in that session. Require the declared current source hash on every revision event, the current compiler identity and expected full/native configuration. Valid revisions must start and exit exactly once with zero status and the exact accumulated output. Invalid revisions must reject with the current diagnostic and never compile/start. Native candidate receipts must partition every current function/entry into compiled/reused lists; trivia and repair must compile none and reuse successful probes. Watcher source checks stay full in both modes. No private cache inspection or separate relinking of the actual watched objects occurs in this runner; actual program task checks are the execution gate. The [object-build measurement](object-rebuild-baseline.md) separately verifies actual cached objects against independently linked C drivers.

## Timing boundaries

For initial startup, stage the source before timing, then measure in the parent from immediately before launching the watcher to receiving its `started` JSON event. This includes Python watcher startup. For subsequent edits, stage a replacement file before timing, then measure from immediately before atomic source replacement to receiving `started` for valid source or `rejected` for invalid source. File replacement, watcher polling/debounce, current checks, native commands, publication and event transport/reading are included. Parent receipt polling uses a 1 ms sleep and parses the bounded JSON log, so its sampling/reading overhead is included. It is a receipt observation duration, not an exact child process launch timestamp.

Keep the watcher's `observed_to_event_seconds` as a separate receipt field: it omits unknown save-to-observation time and uses its own process-local clock. Do not subtract timestamps from different processes. `started` records process creation, not an application readiness signal. Wait for actual program exit and validate output after recording the terminal duration. Source staging, report writes, preflight oracles, correctness checks and final session shutdown are outside timing. Programs finish promptly; long-running application shutdown and concurrent edits/cancellation are not measured here.

Both modes receive identical polling/debounce options (defaults 50/100 ms). Native pipelines retain their implemented at-most-5-ms active delay. Ordinary full builds retain configured polling under the default timeout; an interval at least half the timeout uses shorter completion polling with configured periodic source observation. The first retained run used configured polling for all ordinary full builds. Two separately retained [polling candidates](watch-polling-evidence.md) did not justify changing the default cadence. Preserve source-version distinctions; do not relabel old receipts. This is a comparison of actual modes under the recorded settings, not an isolated object-compilation comparison. Native compilation has its stricter warnings/no-LTO flags; full builds use their ordinary command settings. Record both sets and the separate preflight flags. Alternate whole-session mode order by measured repetition (full/units, units/full, full/units). Each repetition starts empty private caches; warmup sessions are retained but excluded from summaries. OS caches and background scheduling remain uncontrolled.

## Receipts and failures

Archive compiler/runner dependencies, all top-level examples and workload factories, plus each exact source/C/oracle and preflight command output. Retain raw session event/stdout/stderr logs, command arguments, session order, per-revision parent duration and terminal/exit receipts. Record executable hashes, compiler/language version, driver version/target, flags, environment hash/fixed child overrides, CPU/OS, clock implementation/resolution, wall-clock range and configured timing limits. Hashes establish byte identity, not complete toolchain reproduction or authenticated provenance. Logs can contain local paths and trusted tool output; review before public publication.

Create the sample and save it before attempting the edit. Save duration before correctness verification. Unexpected diagnostic/output/status/source identity, missing receipt, tool failure or changed archived input leaves `complete: false`, `passed: false`, `summary: null`, partial samples and logs. Request SIGTERM and wait for watcher cleanup; require exit 143 and `session_stopped`. Forced termination is failed cleanup evidence, never successful session evidence. Bound event/stderr log reads to 16 MiB; this is a measurement reader limit, not an OS disk quota.

Summary generation requires every workload/revision/mode group to contain the requested number of verified nonnegative integer durations. A focused test deliberately supplies wrong watched arithmetic while forging source metadata: the real program's independent task check exits one, and no summary is published. Further tests cover real session reuse/invalid/repair behavior, source/event identity, partial event lines, log limits, required acknowledgement, exact archives and clean shutdown. CI retains a one-repetition run on each declared Linux host; larger local observations must be reported separately.
