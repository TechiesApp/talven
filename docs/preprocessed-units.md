# Prepared hosted function units

Status: implemented reference preparation experiment under [Proposal 0021](proposals/0021-preprocessed-function-units.md), profile `hosted-preprocessed-units-v1`. It extends [checked C units](c-units.md) with a fresh trusted preprocessing pass. Default build/dev behavior is unchanged; objects and an executable are not produced.

~~~sh
python3 -m talven prepare-c-units examples/hello.tal --console --cc cc --timeout 30
~~~

The shared frontend fully checks the current source before any external command. Hosted entry and explicit console requirements match ordinary emission. The command selects the executable through the inherited PATH, copies the current environment with `LC_ALL=C`, probes `--version`/`-dumpmachine`, and runs one preprocessing pass with `-std=c11 -O2 -Wall -Wextra -pedantic-errors -E -x c -`. This requires a trusted GCC/Clang-compatible tool on a POSIX host with process groups and `waitid`; it adds no target or general compiler support claim.

In the default profile, common headers, record layouts and all function declarations precede reserved boundary declarations. Function-local lowering uses the same helpers, arithmetic, stores, calls and static text as ordinary emission. The combined input is for preprocessing only: repeated static helper definitions become separate units after strict boundary validation. Never compile the combined input as one translation unit. Each frozen unit can be compiled separately with `-x cpp-output` and linked under compatible C11/toolchain/ABI settings.

Only generated-input `<stdin>` line-marker numbers are normalized to 1 after macro expansion. System-header filenames, line numbers and flags remain intact. In GCC's documented [preprocessor output format](https://gcc.gnu.org/onlinedocs/cpp/Preprocessor-Output.html), flags identify entry/return and system-header treatment; preserving that treatment matters when compiling expanded host headers with strict warnings. Macro expansions already present in the bytes are not normalized. Default-profile signature/layout/declaration changes conservatively change every unit; unrelated body edits can leave the others byte-identical.

The `talven.preprocessed-units.v1` receipt contains source/compiler/language/profile identities, console selection, compiler executable hash, version, target, fixed flags, effective-environment hash and actual working-directory hash. Environment values and the directory path are not retained as receipt fields. Commands use that captured directory and environment. Standalone calls always probe anew and report `driver_probe_reused: false`; the private object session can reuse successful probes under its separate stable-toolchain contract. It also records the combined preprocessing input hash, raw output hash, normalization rule and ordered `units` with exact frozen `c`/`c_hash`. Headers can include host paths and compiler output is trusted input: this is a local build artifact, not a scrubbed public benchmark result. Hashes neither authenticate tools nor establish native acceptance. Executable/compiler-checkout byte drift before completion fails with `E0501`.

Resource boundaries: 256 functions plus entry; 16 MiB preprocessing input and raw output; 64 MiB combined prepared units and final compact CLI receipt; 64 KiB stderr per command and 64 KiB version/target stdout. The selected timeout is 0.01–60 seconds, default 30, shared across compiler subprocesses. It does not interrupt synchronous frontend work, executable hashing, decoding or serialization and is not an OS CPU/memory quota. Output overflow, malformed boundaries, tool failure or subprocess timeout fails with `E0402`; frontend/receipt limits use `E0005`; unavailable tools/platform use `E0901`. No partial success is printed. Child groups are cleaned up on success and failure.

Ten focused tests cover strict splitting, stable unrelated units, complete receipt identities, invalid-source rejection before execution, drift rejection, environment hashing, fresh standalone probes, subprocess output/time limits and source preservation. Frozen units compile independently with strict warnings and no LTO; native tests verify exact UTF-8/NUL views across functions and all three borrowing fixtures with ASan/UBSan at `-O0`/`-O2`. CI repeats native tests on declared Linux hosts. No preparation-speed, memory, agent-token or incremental-build improvement is established.

The separate [private object-reuse API](object-reuse.md) now tests bounded last-successful storage, byte verification and fresh linking under an explicit trusted stable-toolchain contract. The [opt-in native watcher](native-watch.md) now adds cancellable compiler steps and source-freshness checks before restart. Complete toolchain dependency identity and atomic filesystem publication remain open. A frozen C hash plus driver receipt is not a complete authenticated cache key.

The separate [local function contract profile](local-function-contracts.md) is selected explicitly with `--local-contracts`; existing default profiles retain their conservative global declarations.
