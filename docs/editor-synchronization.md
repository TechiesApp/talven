# Editor document synchronization

The reference LSP advertises UTF-16 positions and incremental synchronization (`textDocumentSync.change: 2`). Clients may send ranged changes or full-text replacements. The server applies each notification's changes in array order to temporary text, then runs the shared full frontend once on the final source. See [Proposal 0030](proposals/0030-incremental-editor-synchronization.md).

This follows the [LSP 3.17 document-change contract](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/textDocument/didChange.md): a later range in a notification refers to the result of preceding changes, not the original snapshot. [UTF-16 positions](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/types/position.md) count an emoji as two code units. Edit positions cannot split such a pair. Columns past a line's length clamp to its end; nonexistent lines, negative/noninteger coordinates and reversed ranges are rejected. LF, CRLF and CR are recognized as editor line boundaries and preserved exactly; this does not change Talven's rejection of lone CR source whitespace.

An optional deprecated `rangeLength` must equal the replaced text's UTF-16 length, including any line-ending units. A change without a range replaces the whole source and cannot supply `rangeLength`. Empty batches can advance the document version. Old/equal versions are ignored before range validation. Documents must be open before changes; closing clears their state and diagnostics.

Each notification has at most 128 changes. Each replacement and intermediate reconstructed source is at most 1 MiB UTF-8. The existing 1 MiB framed-message bound and 32-open-document bound remain. The mirror bound differs from the language's 256 KiB source limit: a larger admitted mirror produces the current shared E0005 diagnostic and can be repaired in later edits. These bounds do not establish measured latency or allocation costs.

A malformed newer batch never publishes partly changed source. It preserves the preceding text snapshot, advances the observed version, clears old analysis/diagnostics and marks the document unsynchronized. All editor queries and further ranged changes return/log an invalid-parameter error until a newer full replacement arrives. A full replacement followed by valid deltas in the same notification can restore the mirror. Close/reopen also clears unsynchronized state. The server cannot infer omitted client text from a bad range; resynchronization is required to avoid displaying stale information.

Valid changes that produce invalid Talven code stay synchronized. Current diagnostics are published, old semantic analysis is discarded, and completion/signature/highlighting use their existing explicitly unchecked or lexical fallbacks on the newly received source. Repair builds a fresh checked model. Other documents are unaffected by a rejected batch.

The server remains read-only: it reads editor text, returns queries/edits for the client, and does not open document URIs or execute native code. Receiving deltas is distinct from incremental parsing/check reuse. Workspace modules, native Rust editor parity and measured editor/model benefits remain open.

[Behavioral tests](../tests/test_document_changes.py) verify text reconstruction, current analyses/diagnostics, UTF-16 and line boundaries, batch limits, stale versions, source limits/repair, blocked stale queries, full resynchronization and a framed stdio hover request. Existing completion, signature, highlighting, rename and formatting tests remain shared regression checks.

Local validation on 2 October 2026 used macOS ARM64 and CPython 3.14.7: all 12 synchronization tests and 22 existing LSP tests passed. The full reference suite ran 476 tests in 215.402 seconds with no failures and one declared Linux-only skip. Documentation validation checked 650 relative links and rendered four Mermaid diagrams. Declared Linux CI hosts require no skips; these local results do not substitute for their native execution evidence or measure editor responsiveness.
