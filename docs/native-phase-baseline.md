# Native in-process phase baseline

Status: implemented experiment, native receipt `talven.native-inprocess.v1` and retained report `talven.native-phase-baseline.v1`. This extends [Proposal 0013](proposals/0013-native-scalar-compiler.md) with measurement of the current declared overlap. It separates native parsing, checking and C emission inside one process. Startup, native C compilation/linking, incremental reuse and end-to-end development feedback are outside this boundary.

## Run and retain

~~~sh
cargo +1.96.0 build --release --offline --locked --manifest-path experiments/native-compiler/Cargo.toml
python3 scripts/measure-native-inprocess.py \
  --native experiments/native-compiler/target/release/talven-native \
  --out build/native-phase-baseline --repetitions 20 --warmups 2 \
  --environment-note 'Describe host and load here'
~~~

Use a new output directory. Python 3.11+, the built Rust experiment, Git and a trusted C11 compiler are required. The runner verifies actual architecture with optional `--expect-arch`, native embedded build sources against the checkout, executable/input fingerprints and declared target. It records Rust version/profile/settings, Python/C identity, CPU/OS, flags, exact sources and native executable, raw command streams, individual samples and summaries. Hash/source matching identifies bytes; it does not authenticate a compiler or host.

The native command is also available directly:

~~~sh
experiments/native-compiler/target/release/talven-native measure examples/hello.tal --iterations 20 --warmups 2
~~~

It reads a bounded regular UTF-8 file once and performs one unmeasured ordinary analysis/emission preflight, followed by labeled warmup/measured iterations. Counts accept ASCII integers, 1–100 iterations and 0–10 warmups; invalid, duplicate or unknown options fail before source reading. This command emits a JSON receipt with exact source, options and C, without executing the program. Emission uses the hosted console-enabled profile. Invalid language/native-entry input reports normal native diagnostics and no successful measurement receipt.

## Timed boundaries

| Field | Boundary |
| --- | --- |
| `parse_ns` | Full source lexing, parsing, AST construction and depth validation |
| `check_ns` | Global declaration/type contracts and all function-body type/move/borrow checking |
| `analysis_ns` | Instrumented analysis as a whole, including timing-call overhead between stages |
| `emit_ns` | Hosted C text emission from the current checked program |

The ordinary `analyze` path performs no clock reads. Both paths use the same private parse/check stages; unchecked parse results are not exposed as public emission inputs. Returned program/C destruction, C equality verification, JSON serialization/output, source I/O and process startup occur outside the core timers. State/allocator/code caches can warm, but every iteration fully parses and checks; this is not persistent semantic reuse. Even zero requested warmups follows the one ordinary preflight.

Each workload is measured in a separate native process with `std::time::Instant` durations in nanoseconds. The Python recorder's enclosing command duration is retained as a different boundary, including startup and all iterations/output. Do not compare an inner analysis sample directly to the [standalone CLI baseline](tooling-baseline.md) or infer startup overhead by subtracting separately scheduled medians. Clock overhead matters for small inputs; no clock calibration, cold-cache or memory result is claimed.

## Workloads and correctness gates

The runner uses Hello World, 32/128-helper chains, a 128-helper/12-store-per-helper source and the borrowing example generated by the [edit baseline](incremental-checking-baseline.md). Only the fixed initial valid revision is measured; this is not that baseline's invalid-edit/recovery sequence.

Before core measurement, reference checking/emission and native emission must agree byte-for-byte. Separate C drivers verify three full-i32 chain results or read/mutation effects and main exit zero; Hello World verifies exact greeting stdout, empty stderr and zero exit. During native iterations, emitted C must equal ordinary native preflight. The retained native receipt must match exact source, profile, options, counts, phase order and accepted C; timing values must be nonnegative integers and the whole-analysis duration must cover its parse/check durations.

Only complete independently accepted measured samples enter summaries. Warmups are excluded; raw values and min/median/max are retained for each phase/workload. Wrong or missing output, malformed receipts, partial samples, input drift, timeout/command failure and existing output directories prevent success. Partial reports retain failure state and no successful summary. CLI and source limits are not hard frontend CPU/RAM quotas.

## Verification

Rust tests compare measured/ordinary emission and rejections. Native conformance tests exercise exact UTF-8 source/C receipts, nested timing boundaries and invalid option/diagnostic behavior. The Python receipt tests reject stale source/output, invalid counts/phases/clock values and partial/unverified summaries, preserving failure receipts and output directories. Compiler CI runs both the existing differential/sanitizer gates and this method on its declared Linux native hosts, retaining separate artifacts.

This evidence can guide work on native parsing/checking/emission and a later backend comparison. It does not select Rust or a backend for production, establish editor responsiveness, prove general speedups or measure model/token/dollar effectiveness.

[Local macOS ARM64 observations](native-phase-evidence.md) retain an actual 50-iteration run and its limits.

The subsequent [emitter buffer comparison](native-emitter-evidence.md) records three interleaved pairs and an archive-replay repair. The runner retains all top-level examples read by the shared workload factory, including filtered cases, and its package initializer.
